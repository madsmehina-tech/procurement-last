## v18.0 — دورة الصرف بثلاث مراحل

**الفكرة:** اعتماد المستخلص، وقرار الإدارة، وتنفيذ التحويل ثلاثة أشياء منفصلة. المبلغ لا يُعتبر مصروفًا إلا عند «تم التحويل».

**ما تغيّر**
- الدورة: إنشاء ← قرار الإدارة ← تنفيذ التحويل (بدل المراحل الخمس).
- «إنشاء دورة صرف» يجمع كل المستخلصات المفتوحة (غير المصروفة بالكامل وغير المقفلة في الأرشيف) من كل المقاولين.
- الشيت: مسلسل، اسم المقاول، رقم المستخلص، المشروع، الموقع، قيمة المستخلص، المصروف سابقاً، المتبقي، الحالة، القرار، مبلغ الصرف، الملاحظات.
- المرحلة النهائية: كل الخانات للقراءة فقط، ويبقى «تم التحويل / لم يتم التنفيذ» لكل مستخلص. «لم يتم التنفيذ» يعيد المستخلص للدورة القادمة حتى لو كان القرار «يصرف».
- خانة «رفع معاملة المستخلص» (اختيارية) تُحفظ في: إدارة مقاولي الباطن ← المقاول ← المستخلصات ← المشروع ← الموقع ← المستخلص رقم N ← الاعتمادات.
- «رفع مستندات الدورة المعتمدة»: نسخة الدورة الموقّعة والمرفقات.
- تعديل الدورة: الرجوع مرحلة في أي وقت، وإعادة فتح دورة مغلقة. حذف الدورة مسموح فقط إذا لم يُسجَّل فيها تحويل.
- سجل كامل لكل دورة (جدول CycleLog): كل قرار ومبلغ وتعديل وإعادة فتح وحذف.
- المستخلص يبقى في الدورات حتى يُسدَّد بالكامل أو تُقفل معاملته في الأرشيف.
- إقفال المعاملة في الأرشيف: لم يعد يشترط السداد الكامل (تبقى الأوراق الخمس شرطًا). ولا يُقفل مستخلص داخل دورة مفتوحة.
- أُزيل: توقيع «الإدارة المالية» من كشف الدورة، وخطوة «أُرسل للمالية»، وملف التحويل البنكي المجمّع، وتصنيف جاهز/مؤجل/موقوف، وسقف السيولة، وإلغاء الدورة (حلّ محله الحذف).
- لم يتغير: أمر الصرف (للنقاش قبل الإطلاق).

**قاعدة البيانات:** الترحيل m020 (يضيف ExecStatus وExecAt وExecBy على CycleDecisions، وينشئ CycleLog). لا يحذف ولا يعدّل أي بيانات موجودة.

**إصلاحات**
- كان الصرف المباشر لمستخلص داخل دورة يحوّل إلى صفحة غير موجودة (`cycle_transfers`) فيسقط بخطأ؛ يحوّل الآن إلى صفحة الدورة.
