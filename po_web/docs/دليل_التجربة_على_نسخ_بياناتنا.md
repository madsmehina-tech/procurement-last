# دليل التجربة على نسخ بياناتنا (v27.8)

**القاعدة الذهبية:** لا نضيف مزايا، ولا نغيّر بيانات التشغيل. كل ما هنا يعمل على **نسخ** في مجلد مستقل (`D:\PO_TEST`). نظام التشغيل الحقيقي يبقى كما هو، ولا نحذف منه ولا ننقل.
ولا ترسل لي كلمات مرور ولا قيم مفاتيح في المحادثة (أسماء المصادر فقط).

---
## الجزء 1: أين بياناتي فعلاً؟ (5 دقائق، قراءة فقط)
1. انسخ الملف `tools\where_is_my_data.py` من الحزمة الجديدة إلى أي مكان (يعمل مع أي إصدار قديم أو جديد، ولا يستورد شيئاً من النظام).
2. افتح CMD وشغّله على **مجلد البرنامج الذي تعمل به الآن**:
   ```
   python where_is_my_data.py "D:\po_web" --release "D:\Downloads\po_web_v27_8.zip"
   ```
3. اقرأ النتيجة ودوّن في ورقة (دون أي كلمة مرور):

| ما أدوّنه | أين أجده في النتيجة |
|---|---|
| مسار القاعدة، ومن أين يأتي (config.ini / متغير بيئة / افتراضي) | «قاعدة البيانات» |
| مسار الأرشيف | «الأرشيف» |
| مسار المرفقات القديمة LEGACY_UPLOADS، وهل هو موجود وفيه ملفات | «المرفقات القديمة» |
| مجلد النسخ الاحتياطية، والمكان الثاني | «النسخ الاحتياطية…» |
| مصدر مفتاح الجلسات (ملف أم متغير بيئة) | «مفتاح الجلسات» (يُذكر المصدر دون قيمة) |
| أي سطر فيه **«داخل مجلد البرنامج ← سيُترك خلفك»** | هذا ما سيضيع إن نقلت `config.ini` و`instance` فقط |
| سطور **«ليست في الإصدار الجديد»** و**«عُدّلت يدوياً»** | ملفات خاصة بك داخل مجلد البرنامج |

> **إن ظهر أي سطر «سيُترك خلفك»:** لا تغيّر شيئاً الآن. في التجربة نكتفي بنسخه. وعند الانتقال النهائي (بعد نجاح التجربة) إما تنقل ذلك المجلد معك، أو تضع في `config.ini` مساراً مطلقاً خارج مجلد البرنامج (مثل `D:\PO_Archive`) **قبل** تبديل المجلد. هكذا لا يبدأ النظام الجديد على أرشيف فارغ بالمسار النسبي نفسه.

## الجزء 2: نسخ متسقة (بعد الدوام، النظام متوقف)
أعلن للفريق: لا حفظ ولا نقل ملفات. أوقف النظام (`deploy\stop_server.bat`).
```
mkdir D:\PO_TEST
copy "D:\PO System\PurchaseSystem.accdb" D:\PO_TEST\PurchaseSystem.accdb
robocopy "D:\PO_Archive" "D:\PO_TEST\archive" /E /COPY:DAT /R:2 /W:2 /NFL /NDL /NP
robocopy "D:\po_web\uploads" "D:\PO_TEST\uploads" /E /COPY:DAT /R:2 /W:2 /NFL /NDL /NP
```
(عدّل المسارات حسب ما دوّنته. السطر الأخير فقط إن كان مجلد المرفقات القديمة موجوداً وفيه ملفات. **لا** تستعمل `/MIR` ولا `/MOVE`.) ثم أعد تشغيل النظام الحقيقي.

## الجزء 3: كم مستنداً يعيش في المرفقات القديمة فقط؟
```
python tools\legacy_check.py --db D:\PO_TEST\PurchaseSystem.accdb --archive D:\PO_TEST\archive --legacy D:\PO_TEST\uploads
```
- **صفر** ← لا إجراء خاص. سجّل النتيجة.
- **أكثر من صفر** ← لا تفعل شيئاً إضافياً بالبيانات: النسخة الاحتياطية تشملها تلقائياً (مرآة `legacy\`)، واختبار القبول يستعمل `--legacy-copy`، والاسترجاع يعيدها إلى مجلد مستقل ويفحص الروابط منه وحده.
- يفحص الجداول: Documents وأعمدة الملفات القديمة (العقد الموقّع، السجل التجاري، الشهادات، سند الصرف…).

## الجزء 4: نسخة اختبار مستقلة من البرنامج (لا تلمس التشغيل)
1. فك `po_web_v27_8.zip` في `D:\PO_TEST\app`.
2. أنشئ `D:\PO_TEST\app\config.ini` (انسخ `config.ini.example` ثم اجعل **كل** المسارات داخل `D:\PO_TEST`):
   ```
   [database]
   path = D:\PO_TEST\PurchaseSystem.accdb
   [storage]
   archive_root = D:\PO_TEST\archive
   legacy_uploads = D:\PO_TEST\uploads
   backup_dir = D:\PO_TEST\own_backups
   backup_auto_hours = 0
   [server]
   port = 5001
   environment = staging
   log_dir = D:\PO_TEST\logs
   ```
   (لا تضع `backup_extra_dir` ولا `backup_archive_dir` إلى مجلدات التشغيل.)
3. **لا تنسخ** `instance` من التشغيل: للتجربة مفتاحها الخاص (ينشأ وحده).
4. تأكد أن لا متغيرات بيئة تشير للتشغيل، وأن التثبيت معزول:
   ```
   python D:\PO_TEST\app\tools\where_is_my_data.py "D:\PO_TEST\app" --must-be-inside "D:\PO_TEST"
   ```
   يجب أن يظهر **«✔ كل المسارات داخل D:\PO_TEST: التثبيت معزول»**. وإن ظهر `[!!] خارج` أو «متغير البيئة PO_…» فصحّح قبل المتابعة.
5. من `D:\PO_TEST\app`: `pip install -r requirements.txt` (بايثون 3.11 أو أحدث) ثم `python migrate.py` ثم `python tools\setup_check.py`. لن يمسّ هذا إلا النسخة.

## الجزء 5: اختبار Access والاسترجاع (على النسخ)
```
python tools\acceptance_check.py --db-copy D:\PO_TEST\PurchaseSystem.accdb --archive-copy D:\PO_TEST\archive --legacy-copy D:\PO_TEST\uploads --work D:\PO_TEST\work --full-hash
```
(احذف `--legacy-copy` إن لم يوجد مجلد قديم.) أثناء الاسترجاع تُعزل نسختا الأرشيف والمرفقات القديمة (تُعاد تسميتهما مؤقتاً) فلا ينجح رابط إلا إن وُجد ملفه في **الأماكن المسترجعة نفسها**. اقرأ التقرير (`acceptance_report.md`) ثم أرسل لي الملفين `acceptance_report.md` و`.json` بعد مراجعتهما.
ولحماية أقوى شغّله بحساب ويندوز لا يملك صلاحية الكتابة على مجلدات التشغيل.

## الجزء 6: تجربتك مع زميل من جهازين (على نسخة الاختبار، منفذ 5001)
شغّل `python serve.py` من `D:\PO_TEST\app` وافتح `http://اسم-الجهاز:5001` من جهازين. لا يحمل أي منكما مستنداً تشغيلياً حقيقياً: كل ما تفعلونه على النسخة.

| # | الاختبار | المتوقع | الفعلي | ✔/✘ |
|---|---|---|---|---|
| 1 | دخول كل منكما بصلاحيته، وظهور القوائم المناسبة فقط | يدخلان؛ كل واحد يرى ما يخصه | | |
| 2 | إنشاء أمر شراء من الخطوات الثلاث وحفظه | يظهر ورقمه تسلسلي وPDF في الأرشيف | | |
| 3 | فتح الأمر نفسه للتعديل من الجهازين، حفظ الأول ثم الثاني | رسالة تعارض عند الثاني ولا ضياع | | |
| 4 | رفع مستند، وفتحه من الجهاز الآخر | يُفتح من مجلد الأرشيف التجريبي | | |
| 5 | مستخلص جديد ← دورة صرف ← قرار إدارة ← تحويل ← إغلاق الدورة | الأرصدة تتحرك مرة واحدة | | |
| 6 | تسجيل «لم يتم التنفيذ» ثم «تغيير الحالة» | المبلغ يعود للدورة القادمة ولا يُحتسب مصروفاً | | |
| 7 | أمر صرف عام بخيار «إضافة لكشف الحساب» | يظهر في الكشف مرة واحدة فقط | | |
| 8 | طباعة أمر شراء وأمر صرف | شكل صحيح، عربي صحيح | | |
| 9 | بحث شامل عن مورد ومقاول ورقم أمر | نتائج صحيحة | | |
| 10 | فتح 10 مستندات قديمة معروفة لكما (2 على الأقل من المرفقات القديمة إن وُجدت) | كلها تُفتح | | |

### مراجعة الأرصدة (قبل التجربة وبعدها)
اختر 5 مقاولين و5 موردين تعرف أرصدتهم. سجّل رصيد كل منهم من **النظام الحقيقي** ومن **نسخة الاختبار** (قبل أي إدخال)، ويجب أن يتطابقا. وبعد تجربتكما تحقق أن الفرق = ما أدخلتماه فقط.

| الجهة | الرصيد في الحقيقي | الرصيد في النسخة (قبل) | الرصيد (بعد) | ما أدخلناه | مطابق؟ |
|---|---|---|---|---|---|

## الجزء 7: استرجاع من النسخة الاحتياطية في أماكن مستقلة
بعد الجزء 5 تجد النسخة في `D:\PO_TEST\work\backup_set`. جرّب الاسترجاع يدوياً في مكان جديد:
```
python tools\restore_all.py --set D:\PO_TEST\work\backup_set --db-out D:\PO_RESTORE\restored.accdb --archive-out D:\PO_RESTORE\archive --legacy-out D:\PO_RESTORE\legacy --verify full
```
ثم افتح عدة ملفات **من المجلد المسترجع** (`D:\PO_RESTORE\archive`). وللتأكد من الاستقلال أعد تسمية `D:\PO_TEST\archive` و`D:\PO_TEST\uploads` مؤقتاً ثم افتح المستندات من النسخة المسترجعة.

## بعد التجربة
- أرسل لي: تقرير القبول، ونتيجة `legacy_check`، ونتيجة `where_is_my_data` (الأقسام التي دوّنتها)، وجدول الاختبارات والأرصدة.
- احذف `D:\PO_TEST` و`D:\PO_RESTORE` (فيهما نسخة من بيانات الشركة).
- لا انتقال للتشغيل قبل مراجعة النتائج معاً.
